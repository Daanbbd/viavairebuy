Rebuy — Overzicht

Alle vier de Rebuy-gedreven onderdelen van deze integratie, uitgewerkt op mobile (375px) en desktop (1400px — --page-width), inclusief elke functionele staat die development nodig heeft: filled, fallback, empty/no-results, hover en loading.

Niet op deze pagina: de post-purchase upsell. Die draait volledig binnen Rebuy's eigen gehoste template zonder VIA VAI-styling en is daarom geen design-onderwerp.

Rebuy-toggle annotatie Mechanisme·Databron (fallback indien van toepassing)

Elk Rebuy-element draagt deze pil zodat een niet-technische stakeholder in één oogopslag ziet welk Rebuy-mechanisme (Widget / Smart Cart / Bundle Builder) het aandrijft, en welke databron het voedt. Tekstkleur ink-op-tint = 11.6:1 contrast, cognac-dark-op-tint = 4.9:1 — beide ruim boven de WCAG AA-eis van 4.5:1.

Dev notes — Aanbevelingen (beide plaatsingen) — precieze interactiemechaniek, geverifieerd via DevTools op de live BBD-FEATURED-PRODUCTS / BBD-CARD-PRODUCT custom elements
  • Desktop (≥990px), zuiver CSS, geen JS: .card:hover/:focus-within flipt vier custom properties op de kaart: --sizes-translate (translateY(100%) → translateY(-2px)), --sizes-icon-plus-display (flex → none), --sizes-icon-minus-display (none → flex) en --growave-opacity (0 → 1, het hartje is dus onzichtbaar tot hover). :focus-within zorgt dat toetsenbordgebruikers die naar een focusbaar element ín de kaart tabben (bv. het hartje) dezelfde reveal krijgen als bij hover.
  • De maat-tray (.card-sizes, in werkelijkheid een <product-form data-type="add-to-cart-form">) staat op position:absolute; inset:auto 0 0 0 — vastgepind aan de onderrand van de afbeelding — met transform:var(--sizes-translate) en transition:transform .3s ease-in-out. In rust staat hij volledig onder de afbeelding (onzichtbaar); bij hover schuift hij omhoog tot nagenoeg vlak met de onderkant.
  • De +/− knop (.card-sizes__button) staat op position:absolute; right:0; bottom:100% — dus ten opzichte van de tray zelf, net erboven. Effect van de transform-wiskunde: in rust (tray verborgen) landt deze knop daardoor precies rechtsonder in beeld, vlak met de afbeelding — zoals elke gewone productkaart; bij hover schuift hij mee omhoog tot net boven de nu zichtbare tray. Op desktop heeft hij pointer-events:none — hij is puur decoratief, de hele kaart-hover doet het werk. Let op: een toetsenbordgebruiker kan deze knop nog wel focussen en met Enter "activeren" zonder effect (pointer-events blokkeert alleen muis/touch, niet keyboard-activatie) — controleer of de live Vue-implementatie hier tabindex="-1" op desktop zet, of accepteer de no-op bewust. Correctie 20-08-2026 (klantfeedback): background:transparent, geen witte achtergrond-vierkant achter het icoon — het icoon staat los, direct op de productfoto.
  • Correctie 20-08-2026 (klantfeedback: "de mobiele kaarten hebben nog hover, dat zou niet moeten"): in deze reviewpagina draaien .frame--mobile-kaarten gewoon in een desktopbrowser, dus een echte muis-hover erover triggerde per ongeluk tóch de :hover-CSS hierboven — iets wat op een echt touchscreen nooit kan gebeuren (geen :hover-pseudo-class op touch), maar hier wel zichtbaar was. Gefixt door de tray-reveal, de plus/min-icoonwissel én de fotowissel expliciet te scopen tot .frame--desktop .card:hover/:focus-within (zie de CSS-comments hierboven); .frame--mobile toont het open/dicht-verschil uitsluitend via de losstaande .is-tapped-documentatieklasse. Dit is puur een noodzaak van déze demonstratiepagina (twee frames naast elkaar in één browser) — de echte Vue-implementatie op een echt mobiel toestel heeft deze scoping niet nodig, daar vuurt :hover sowieso nooit.
  • Alleen het icoon wisselt (plus↔min) via de twee display-variabelen hierboven — geen los aan/uit-element, gewoon dezelfde knop met twee kinderen waarvan er telkens één display:none heeft.
  • Afbeelding: als er een tweede foto is, faden img:first-child (naar opacity 0) en de tweede img (naar opacity 1) in elkaar over — zie de .card__media--swap-kaarten hierboven (June Loua desktop, Elisa Palmer in Plaatsing A). Is er maar één foto, dan gebeurt er niets op hover — geen schaal/zoom-effect. Correctie 20-08-2026 (klantfeedback tegen de live site): een eerdere aanname dat single-image kaarten naar scale(1.03) zouden gaan bleek niet te kloppen met wat er nu live staat — verwijderd uit zowel de CSS hierboven als deze toelichting.
  • Een maat aanklikken submit het <product-form> direct (variant toevoegen zonder page-navigatie); de knop krijgt een loading-class terwijl dat gebeurt (tekst wordt transparant, spinner erover) — zie de "39"/"38"-voorbeelden hierboven. Niet-beschikbare maten krijgen .card-sizes__size--unavailable: gedempte kleur, cursor:not-allowed, geen hover-effect, pointer-events:none.
  • Mobile (<990px), JS-gedreven, geen hover: touch kent geen :hover, dus bovenstaande CSS vuurt niet. In plaats daarvan heeft .card-sizes__button op mobile pointer-events:auto — een tik schakelt de tray programmatisch (dezelfde vier custom properties, maar nu via JS in plaats van :hover). Hierboven gesimuleerd met de documentatie-only .is-tapped-class binnen .frame--mobile, om het open/dicht-verschil te tonen zonder een echte touch-event te kunnen spelen. Geen fotowissel en geen schaal-effect op tik.
  • Het wishlist-hartje (--growave-opacity) staat op mobile altijd op 1 (geen hover-gate) — let op de afwijkende breakpoint: dit kantelt bij <768px, niet bij de 990px van de hover/JS-tray-split. Twee verschillende breakpoints in hetzelfde component — bevestig dit bewust bij implementatie, het is geen typefout in deze documentatie.
  • Kleurvarianten (.bbd-color-variation): platte, niet-interactieve <div>s — geen links/knoppen, geen klik-gedrag, exact zoals in productie. 12×12px blokjes; effen kleur via --variation-color (hex), patroon/multicolor via een kind-element .bbd-color-variation__image met background-image (zie de streep-swatch bij June Loua). Wit krijgt een haarlijn-rand om zichtbaar te blijven; de actieve swatch krijgt border:1px solid rgb(var(--color-link)) — --color-link staat nog niet in colors_and_type.css, hier vervangen door --vv-ink als plaatsvervanger totdat het echte token bevestigd is. Overflow voorbij een paar swatches toont een "+N"-label (.bbd-color-variation__remainder). Het kleurnaam-label is altijd .visually-hidden (alleen voor screenreaders).
  • Rebuy widgets laden client-side na page load → reserveer de skel-media-hoogte (aspect-ratio 3/4) vooraf server-side om Cumulative Layout Shift te voorkomen.
  • .card-sizes__button en .card__wishlist zijn nu 44×44px hit-areas (was 40×40 / geen expliciete maat in de eerder goedgekeurde comp-rebuy-pdp-crosssell.html) — pas dat bestand gelijktrekken vóór implementatie. Ook de klassennamen daar (.sizes/.add/.heart) zijn een vereenvoudigde benadering; deze pagina volgt nu de echte BBD-CARD-PRODUCT-klassen (.card-sizes, .card-sizes__button, .card__wishlist).
  • Focusring op .card-sizes__button/.card__wishlist gebruikt outline-offset:-2px zodat hij niet wordt afgesneden door .card__media{overflow:hidden}.

Dev notes — Bundel
  • .bcard__stack (46×46px, witte 2px rand + zachte schaduw) toont het tweede bundelitem gestapeld linksonder op de hoofdfoto — enige plek in het systeem waar een schaduw wordt toegepast buiten --shadow-popup; hier bewust om de twee gestapelde vlakken visueel te scheiden.
  • .badge--bundle hergebruikt de bestaande .badge-pil-component (cognac achtergrond, 40px radius) — geen nieuw badge-type nodig.
  • +-knop rechtsonder voegt in één klik de volledige bundel toe (hoofdproduct + accessoire), niet alleen het hoofdproduct — pas aria-label hierop aan zoals getoond.
  • Bij toegevoegde maatafhankelijkheid: de .sizes-strip selecteert alleen de maat van het hoofdproduct; het accessoire-item heeft doorgaans geen maat en wordt automatisch meegevoegd.
